# 02 · 语音系统

## 架构

```
前端 useTTS.ts
  └─ POST /api/v1/tts/synthesize {text, voice, rate, engine}
       └─ server routes/tts.ts → ttsService
            └─ cosyVoiceProxy（懒启动侧车）
                 └─ POST http://127.0.0.1:12001/synthesize
                      └─ tts_sidecar.py（FastAPI + CosyVoice2-0.5B）
                           └─ 返回 wav 文件路径 → server 转 base64 → 前端播放
```

## 侧车（tts_sidecar.py）

- **单文件** FastAPI 应用，端口 12001
- **懒加载模型**：首次合成请求才加载 CosyVoice2-0.5B（30-60s），后续毫秒级
- **模型定位优先级**：
  1. 环境变量 `COSYVOICE_MODEL_DIR`
  2. `CosyVoice-unzip/cosyvoice-main/pretrained_models/CosyVoice2-0.5B`
- **项目根定位**：环境变量 `COSYVOICE_PROJECT_DIR` > 自身目录 `CosyVoice-unzip/...`
  （桌面打包版没有模型，靠后端注入本机路径）

## 后端代理（cosyVoiceProxy.ts）

- **懒启动**：首次合成时 spawn `conda run -n cosyvoice python tts_sidecar.py --port 12001`
- **健康检查**：`/health` 2s 超时；无响应判死重启
- **等待就绪**：启动后轮询最多 90s（模型加载）
- **失败统计**：failedCount 供上层降级决策
- **findCondaPython 候选**：`COSYVOICE_PYTHON` env > `D:/Anaconda/envs/cosyvoice/python.exe` > 其他常见路径
- **桌面打包版**：spawn 时注入 `COSYVOICE_PROJECT_DIR` 指向本机项目
  （`E:/project/Crow5/Arrodes/Arrodes/tts-sidecar/CosyVoice-unzip/cosyvoice-main`，env 可覆盖）

## 前端（useTTS.ts）

- 引擎固定 `local`（云端已移除）
- **TTS 失败自动回退**：自定义音色（`custom:`）合成失败 → 自动用默认音色重试一次
- **静音模式**：不合成不播放，只显示文字
- **代际计数器**：新请求中断旧音频，防残留
- 错误提示："无法连接语音服务"（voices 加载失败 或 合成失败）

## 故障排查

| 症状 | 可能原因 | 处理 |
|------|---------|------|
| 无法连接语音服务（dev） | 侧车没起来/模型加载失败 | 看后端日志 `[CosyVoice]`；手动跑侧车脚本看报错 |
| 无法连接语音服务（打包版） | ①打包缺 tts-sidecar 脚本 ②本机无 cosyvoice 环境/模型 | 用 release6+；确认本机有 cosyvoice conda 环境 + 模型 |
| 首次语音很慢（30-60s） | 模型首次加载 | 正常；之后毫秒级 |
| CUDA 不可用 | 无 GPU | 自动回退 CPU（fp16 关闭） |
| 模型目录不存在报错 | 权重未下载 | 按报错提示用 modelscope/huggingface 下载到 pretrained_models |

## 自定义音色（T9 克隆）

- 目录：`tts-sidecar/custom-voices/`
- API：`GET /api/v1/tts/custom-voices`
- 前端 `custom:<id>` 音色 → 后端取参考音频路径 + 提示文本 → 侧车 zero-shot 克隆
- 参考音频配套提示文本：`"你好，我是你的专属语音助手。"`

## 依赖锁定

- `tts-sidecar/requirements.txt`：核心依赖实测版本（torch 2.4.1+cu121 / fastapi / onnxruntime / matcha-tts 等）+ CosyVoice 官方依赖（去 linux-only）
