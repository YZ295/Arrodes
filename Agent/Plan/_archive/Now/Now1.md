## 二、已完成工作

### 2.1 `useSpeechToText.ts`（新建）

封装浏览器原生 `SpeechRecognition` API，全程不依赖后端。





| 功能     | 实现                                                         |
| -------- | ------------------------------------------------------------ |
| 中文识别 | `lang: 'zh-CN'`                                              |
| 实时转写 | `interimResults: true`，中间结果通过 `interimText` 实时暴露  |
| 自动发送 | `isFinal: true` 时触发 `onResult` 回调                       |
| 静默重试 | 识别失败（网络/权限/无语音）自动重试 2 次                    |
| 错误分类 | `'not-allowed'` | `'no-speech'` | `'network'` | `'aborted'` | `'unknown'` |
| 资源释放 | `abort()` 方法取消进行中的识别会话                           |

### 2.2 `useVoiceChat.ts`（重写）





| 功能     | 实现                                                         |
| -------- | ------------------------------------------------------------ |
| STT 集成 | 录制结束后自动启动 `useSpeechToText`，识别结果作为消息内容发送 |
| 识别降级 | 识别失败时自动降级为 `[语音消息]` 占位符                     |
| TTS 集成 | AI 回复完成后自动调用 `speechSynthesis.speak()`，播报中文语音 |
| TTS 状态 | `isSpeaking` 暴露给 UI（显示播放指示器）                     |
| 消息恢复 | 创建会话后自动请求 `GET /api/v1/messages/{id}` 恢复历史      |
| 本地缓存 | 消息自动写入 `localStorage`，刷新不丢                        |

### 2.3 `VoiceDialog.tsx`（更新）





| 改动               | 说明                               |
| ------------------ | ---------------------------------- |
| 解构 `interimText` | 转写中实时文本条，显示在输入框上方 |
| 解构 `isSpeaking`  | TTS 播放中指示器，显示在状态栏     |
| 界面渲染           | 两个新状态均已挂载到 UI            |

### 2.4 技术决策





| 决策                           | 理由                                   |
| ------------------------------ | -------------------------------------- |
| 用 Web Speech API 做 STT       | 零依赖、零成本、中文可用，MVP 最快路径 |
| 用 Web Speech API 做 TTS       | 同上，5 行代码就能出声                 |
| 前端模拟 AI 回复（暂不接后端） | 先让语音交互闭环，后端 LLM 后续替换    |
| localStorage 消息持久化        | 刷新不丢，无需等待后端 DB              |
