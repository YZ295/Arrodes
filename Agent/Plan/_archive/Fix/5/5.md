## 三、分阶段执行计划（顺序不可颠倒）
### 阶段1：TypeScript 编译校验（优先级最高，P0）
#### 执行命令
```bash
npm run tsc --noEmit
```
#### 执行判定规则
1. 输出无报错：直接进入阶段2清理冗余文件；
2. 存在类型报错：暂停后续流程，修复 `VoiceDialog.tsx` 内联函数、接口定义，重新执行校验直至零错误。
#### 交付物
TS 类型校验通过日志，无编译异常。

### 阶段2：清理所有无关脏变更（P0）
1. 恢复流水线自动生成文件，丢弃本次改动
```bash
git checkout HEAD spec/state.json spec/status.md
```
2. 删除无关残留文件与临时规划目录
```bash
rm -rf assistant-x-openclaw
rm -rf Arrodes/Plan/Fix/4/
```
3. 清除全部未跟踪临时文件
```bash
git clean -fd
```
#### 执行后校验
执行 `git status`，仅展示本次Fix3相关源码变更，无临时文件、无关文件、流水线状态文件改动。

### 阶段3：Git 规范暂存变更文件（P0）
仅将本次重构相关文件加入暂存区，不包含任何冗余内容：
```bash
# 核心修改文件
git add src/VoiceDialog.tsx
# 已删除的三个独立组件（标记删除状态）
git add src/ChatInput.tsx src/MessageList.tsx src/MessageBubble.tsx
# 变更跟踪目录纳入版本管理
git add spec/changes/
```
#### 校验标准
`git status` 仅显示4项变更：
1. modified: src/VoiceDialog.tsx
2. deleted: src/ChatInput.tsx
3. deleted: src/MessageList.tsx
4. deleted: src/MessageBubble.tsx
5. modified: spec/changes/（目录跟踪更新）

### 阶段4：标准化Git提交
```bash
git commit -m "hotfix(Fix3): 内联ChatInput/MessageList/MessageBubble至VoiceDialog，移除独立组件文件，对外组件接口保持不变，无业务逻辑改动"
```
#### 提交规范要求
- 明确标记 hotfix 与修复编号 Fix3；
- 写明改动内容、兼容性说明；
- 区分重构范围，说明语音钩子未改动，规避回归风险。

### 阶段5：更新Wu5流水线审批状态
提交完成后执行流水线脚本，刷新hotfix审批状态为有效：
```bash
python wu5_flow.py --fix-status fix3 --approve
```
#### 校验标准
流水线输出提示「Fix3 hotfix 审批状态已更新为有效」，可正常发起合并。

## 五、风险预案
1. **TS编译报错**
    暂停清理与提交，定位 `VoiceDialog.tsx` 内联函数缺少的类型定义、传参不匹配问题，修复后重新校验。
2. **清理命令误删业务文件**
    通过 `git checkout HEAD 目标文件路径` 恢复代码，核对目录后重新执行清理。
3. **流水线脚本执行失败**
    核对脚本路径、fix编号参数，确认Wu5环境依赖正常，手动同步审批状态。
