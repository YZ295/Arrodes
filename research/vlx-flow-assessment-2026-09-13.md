# VLX-Flow 对阿罗德斯的适用性判断

研究日期：2026-09-13

## 判断

VLX-Flow 确实是流式视频理解模型设计。它将连续视频切成小片段，逐段编码并更新内部状态；用户提问时复用已经积累的状态，不从头重算全部视频。

但它目前不能作为阿罗德斯的可用依赖。官方仓库只有 README、演示素材和许可证，没有训练代码、推理代码、模型配置或权重；官方仍将 checkpoints 标记为 `Coming soon`。现在能确认的是设计主张，不能确认真实精度、吞吐、延迟、显存占用和 Windows 部署能力。

2026-09-13 用户已实际测试 Qwen3-VL，并根据对比体验决定淘汰 Mage-VL；Qwen3-VL 已确定为当前主视觉模型。下文涉及 Mage-VL 的内容只表示研究当时的旧基线，后续比较改用 Qwen3-VL。用户测试足以确定模型选型，但不自动代表 Arduino IDE → 结构化观察 → 管家投影 → 步骤验证的完整产品链路已经验收。

## 它所说的“流式”

VLX-Flow 不是把每一帧持续交给大语言模型生成文字。其设计是：

```text
连续视频 → 小片段 → 视觉编码
                    ↓
        近期视觉缓存 + 长程语义状态
                    ↓
          提问或事件触发时生成回答
```

近期视觉缓存保存动作和位置等细节；语义状态保存已经压缩的事件关系和交互历史。语言模型含 Linear Attention 组件，以递推状态减少长视频造成的 KV cache 增长。

这比阿罗德斯当前“画面变化 → 截图 → Qwen3-VL 单次分析”的候选方案更接近真正的连续时序理解，可以回答“刚才发生了什么”，也更不容易漏掉两次抽帧之间的短动作。

## 对最小屏幕闭环的真实价值

阿罗德斯当前首个验收是 Arduino IDE 的编译成功与失败。完成它主要依赖界面文字、按钮状态和编译日志，Qwen3-VL 单帧结构化观察加变化检测应当足够，但仍须用真实屏幕闭环验证。VLX-Flow 的时序优势不是这个验收的必要条件。

它未来可能解决的任务包括：

- 用户连续完成多步操作后，恢复动作顺序；
- 游戏、视频或摄像头中识别短暂事件；
- 用户随时询问“刚才发生了什么”；
- 长时间观察时避免重复编码全部历史。

它不能单独解决：

- 下一步应该做什么；
- 当前步骤是否符合任务目标；
- 屏幕文字中的提示注入；
- 高风险动作授权；
- 跨任务长期记忆；
- 桌面操作和结果验证。

## 当前决定

1. 不下载、不接入、不为它改现有架构。
2. 使用“廉价变化检测 + 事件触发 Qwen3-VL + 结构化证据规则”完成最小屏幕闭环。模型选型不再等待重复对比；后续只验证产品链路并清理 Mage-VL 回退。
3. 将“连续动作在抽帧间丢失”设为未来重新评估的触发条件。
4. 只有官方发布权重和推理代码后，才用同一段录屏对比 VLX-Flow 与 Qwen3-VL 事件触发方案的事件召回率、误报率、端到端延迟和峰值显存。
5. 8 GB 显存是硬约束；没有实测数据前，不根据“面向端侧”的描述推断本机可运行。
