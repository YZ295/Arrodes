# 变更提案：seminar-context

## 问题与背景

T-08 多方研讨会把「完整历史」拼进每个 agent 的任务文本，人数×轮数线性膨胀：

- Hermes CLI 适配器把任务截断到 4000 字符，超过后**前面的发言直接丢失**
- codex 等长上下文 agent 虽能容纳，但历史过长会稀释注意力、抬高成本
- 三方 1 轮（约 3-5k 字）已接近 Hermes 截断线；2-3 轮必然丢上下文

## 目标

- 研讨会历史采用 AutoGen 式滚动摘要：超过阈值后，早期轮次压缩为阶段摘要，保留最近一轮原文
- 任何规模下每个 agent 看到的上下文有界（摘要 + 最近轮），不丢早期信息

## 非目标

- 修改各 CLI 适配器的截断策略（那是 agent 侧限制，本变更在上游规避）
- A2A 协议、私有上下文注入（后续独立变更）

## 影响范围

- server：`seminarService` 增加滚动摘要逻辑（runSeminar + buildSeminarPrompt + 摘要生成）

## 风险

- 摘要本身调用 LLM，增加一轮成本：仅在历史超阈值时触发（默认 3000 字符）
- 摘要质量影响早期信息：提示词要求「只保留影响后续讨论的关键观点」
- 不改变落库消息（messages 仍全量保存），只影响发送给 agent 的任务文本

## 验收标准

- 短历史（< 阈值）行为不变：仍拼完整历史
- 长历史：每个 agent 的任务文本 = 早期摘要 + 最近一轮原文，且总长有界
- 落库消息保持全量，学习提炼仍基于全量 transcript
