# 变更提案：seminar-multi

## 问题与背景

T-07 研讨会仅支持两个 agent（A/B）交替对话。用户要求「agent 之间可以互相对话学习，
组成真正的多 Agent」——真正的多 Agent 需要多方同时研讨，而不只是两两对话。
此外，两方分歧时没有仲裁者，学习小结缺少中枢的倾向性结论。

## 目标

- 研讨会支持 2-5 个已接入 agent 轮流发言（多方群聊）
- 阿罗德斯作为中枢，在提炼学习时对分歧给出「裁决」段（第五段）
- 兼容存量数据：agent_a/agent_b 保留，新增 participants 列表

## 非目标

- A2A 协议跨框架互信（后续单独变更）
- 按 agent 裁剪的私有上下文注入（存储-注入分离已满足：存储全量、注入按来源裁剪）
- 研讨会投票/表决机制

## 影响范围

- server：`workspace_seminars` 加 `participants` 列（幂等迁移）；`seminarService` 多方轮转 + 仲裁段；路由接受 `agents[]`
- client：`SeminarDialog` 多选参与者（chips 选择 2-5 个）

## 风险

- 多方上下文膨胀：每轮每人发言，轮数×人数 次 LLM 调用，默认轮数需约束（1-3 轮，≤5 人）
- 兼容性：旧记录无 participants → 用 agent_a/agent_b 回退
- 迁移：老库加列幂等，不破坏现有研讨会

## 验收标准

- 创建研讨会可传 2-5 个 agent，全部轮流发言且历史可见
- 提炼输出含「裁决」段（分歧存在时）
- 旧记录（无 participants）查询/展示正常
