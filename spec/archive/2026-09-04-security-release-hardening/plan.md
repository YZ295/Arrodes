# 实施计划：security-release-hardening

> 本文件批准后保持不可变；任务进度写入 `spec/state.json`。

## 任务

1. **建立本地访问边界（REQ-001）**
   - 新增服务端本地访问策略及测试：正确临时凭据 + 允许 UI Origin 才可通过；缺凭据、错误凭据、错误 Origin 均拒绝。
   - 将开放 CORS 替换为该策略，受保护 `/api` 路由和 `/v1/chat` 握手共用校验，服务仅监听 `127.0.0.1`；`/api/health` 保持最小公开启动探测。
   - Electron 主进程生成令牌，启动健康检查后、加载窗口前写入 HttpOnly 严格同站 Cookie，并传递允许的 UI Origin；不提供开放模式回退。

2. **绑定动作所有权与连接任务（REQ-002、REQ-004）**
   - 先扩展 `actionGate.test.ts`：待确认动作只能由相同本地用户、工作区和会话查询、确认或拒绝；任何“自动批准”配置不绕过高风险确认。
   - 新增异步动作上下文，令技能预钩子从 WebSocket 已验证会话取得所有权；将所有权与延迟执行器一起保存。文本确认和 REST 确认均从服务器端会话反查工作区，再只查询匹配项。
   - 将 WebSocket 进行中任务表下沉至单个连接；新增连接关闭隔离和同连接重复请求取消的测试；移除全局任务表和全局 `getLatest()` 确认。
   - 移除工作区 PATCH 对全局自动批准的副作用；保留外部 Agent 适配器的工作区权限语义，但不让它放行本体高风险工具。

3. **实现目录能力 allowlist（REQ-003）**
   - 先新增目录授权服务测试：项目根与显式额外根可用、前缀相近目录不可用、相对路径和真实路径/符号链接逃逸不可用、复制/移动两端均受约束、撤销后待确认操作不再可执行。
   - 扩展工作区配置读写，规范化和持久化 `authorizedDirs`；在工作区面板复用文件夹选择器实现添加和撤销额外目录。
   - 将文件技能的每个入口改为在执行时从动作上下文取得工作区授权根，并为现有路径和待创建路径分别做规范化校验；没有授权上下文或授权根时拒绝。删除基于危险路径片段的主授权逻辑。

4. **收紧视觉资源生命周期（REQ-005）**
   - 先补充视觉校验/路由测试：只接受 JPEG、PNG、GIF、WebP；Base64 格式、解码大小、签名和声明格式不一致均拒绝；模型异常后上传临时文件为空。
   - 抽取可复用的格式、大小和超时常量；为 JSON 解析器设置相匹配上限，为远端视觉请求设置超时。
   - 将 multipart 路由改为以 `finally` 清理，并在 Multer 错误链路清理可能已创建的文件；保持现有一致的错误 JSON 契约。

5. **修复发布闸门与依赖告警（REQ-006）**
   - 先增加脚本配置断言或等价静态验证：服务端测试只发现 `src`，桌面 `pack` 和 `dist` 都先构建服务端与客户端。
   - 修正 package scripts；以最小范围更新锁文件/依赖，消除生产 `qs` 审计告警，并复跑完整验证。
   - 不触及 `pre-security-release-hardening-user-wip` 中的 DSH 市场源码和测试；它恢复后另起变更处理。

6. **验证与审查**
   - 依次保存 RED 输出、实施后的相关测试 GREEN 输出、重构后完整服务端测试、类型检查、客户端测试/lint/build、桌面构建、生产依赖审计和 `git diff --check`。
   - 更新 `verification.md`，复读规格逐项检查，再按代码审查技能完成独立的变更审查。只汇报结果；不提交、推送或合并。
