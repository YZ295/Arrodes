# 变更提案：security-release-hardening

## 问题与背景

阿罗德斯是可读写本地文件、执行桌面动作并调用模型的桌面 Agent。当前安全审查发现：服务访问边界、待确认动作归属、文件路径范围、任务隔离和发布验证未形成闭环；视觉处理还会遗留用户上传文件。现状会使单机用户数据、动作确认和发布质量暴露于不必要风险。

## 目标

- 让只有已启动阿罗德斯的用户界面能够访问其敏感功能。
- 让每一项高风险动作只可由其发起者确认或取消。
- 让文件能力仅访问用户已授权的范围，且不会因其他会话断开而相互影响。
- 让视觉和发布验证具有可检查的安全与失败处理行为。

## 非目标

- 不新增远程协作、账户体系或云端多用户产品能力。
- 不改变既有对话、语音、壁纸和模型选择的正常交互。
- 不恢复或修改独立暂存的视觉模型与 DSH 市场在途工作。
- 不重新实现暂存中的 DSH 市场文件；恢复该在途工作后，再以独立变更审查其目录来源和安装边界。

## 影响范围

- 本地使用者与桌面客户端。
- 高风险工具确认、文件操作、对话任务、视觉处理与发布验证。

## 风险

- 收紧边界可能使依赖未授权访问的本地开发或脚本失效。
- 文件范围策略需要兼容“用户可选择任意驱动器目录”的既有体验。
- DSH 市场目前不在干净基线中；若与暂存内容并行修改，会产生覆盖和重复实现风险。

## 验收标准

- 未授权来源不能读取私有数据、创建动作或确认动作。
- 跨会话的确认、取消与连接关闭互不影响。
- 未获用户授权的文件范围不可读取、列举、写入、移动或复制。
- 上传失败、无效或模型失败后不保留临时图片。
- 发布前验证能反映真实源码和测试状态。
