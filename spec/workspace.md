# 业务规范：多 Agent 工作区

> 日期：2026-08-15（2026-09-13 修订：取消全量共享记忆，改为候选 / 确认机制）
> 依据：spec/decisions.md「多 Agent 工作区」D1–D6（D2 / D3 已于 2026-09-13 修订）
> 性质：无代码业务规范（只描述做什么，不描述怎么做）

## 1. 概述

让用户在阿罗德斯的工作区里接入任意 AI 智能体（Codex、DeepSeek Harness 等），与它们对话、派发任务，并把值得跨会话保留的记忆沉淀下来：外部智能体提交**候选记忆**，由阿罗德斯审核后写入 Obsidian 知识库，避免换一个智能体就要重新喂记忆。

范围：多智能体接入、对话、任务派发、候选记忆审核与长期记忆沉淀。

非目标（Non-Goals）：

- 不做自由拖拽画布（列为后续升级，见 FR-9）。
- ~~不做「部分共享」——共享记忆永远是全部。~~（2026-09-13 修订：改为按边界共享，不再全量外发）
- 不承诺外部智能体零改造接入：写入统一经阿罗德斯中转。
- 不做多人协作与细粒度权限（本地单用户）。

## 2. 用户与场景

角色：本地用户（愚者大人）。

主要场景：

- 用户在「大创项目」工作区把 Codex 与 DeepSeek Harness 接入，分别与它们对话。
- 用户向 Codex 派发一次具体任务（例如"把登录页改成深色主题"），Codex 完成后返回结果。
- Codex 在工作区提交一条候选记忆「用户偏好深色主题」；用户在候选队列中确认后，该记忆成为长期记忆并同步到 Obsidian。
- 用户在设置中查看某次任务发送给外部智能体的上下文包，确认其中不含私人记忆。

## 3. 功能需求

- FR-1（MUST）多智能体接入：工作区能发现并列出可接入的智能体（内置智能体与本机可用的外部智能体），并显示各自可用性。
- FR-2（MUST）接入与断开：用户可将某智能体接入当前工作区（即「连线」），也可断开；接入后该智能体成为工作区成员。
- FR-3（MUST）与智能体对话：用户可在工作区与已接入的智能体进行多轮文字对话，智能体的回复展示在对话区。
- FR-4（MUST）派发任务：用户可向已接入的智能体发起一次具体任务，智能体执行完成后返回结果与说明。
- FR-5（MUST，2026-09-13 修订）按边界共享记忆：已接入智能体只能经统一记忆入口读取「已确认」的长期记忆，并按当前任务 / 当前项目 / 用户授权范围获得上下文包；外部智能体写入的记忆一律为**候选**，需经阿罗德斯审核后才可被其他智能体看到。
- FR-6（MUST）统一记忆格式：所有来源的记忆在进入系统时统一为同一结构（内容、类型、作用域、来源、证据、置信度、审核状态、时间、归属工作区），不因来源智能体不同而格式各异。
- FR-7（MUST，2026-09-13 修订）**Obsidian 是长期记忆的权威来源**：
  - 已确认记忆以统一格式写入 Obsidian；笔记分「自动生成区」与「用户正文区」，用户手写内容**永不被同步覆盖**
  - 系统可**从 Obsidian 读回并重建** SQLite 索引 —— SQLite 只是可重建的索引
  - 失效记忆（已拒绝 / 已遗忘）的笔记移入归档区，**不物理删除**
  - 候选与已拒绝的条目不出现在索引中
- FR-7b（MUST）候选审核：外部智能体提交的记忆进入候选队列，用户可逐条确认或拒绝。
- FR-7c（MUST）显式记忆指令一致性：用户说「记住 X」写入长期记忆、说「忘了 X」使其失效；两处操作之后，SQLite 索引、用户画像、召回结果与 Obsidian 必须一致（不能出现「界面上说忘了、Obsidian 里还在」）。
- FR-8（SHOULD）对话记录保留：与智能体的对话随工作区保留，用户可回溯历史对话。
- FR-9（COULD）画布升级：在卡片式布局验收通过后，支持拖拽定位与连线可视化（后续升级项）。
- FR-10（COULD）能力展示：工作区展示每个智能体的能力标签与接入方式说明，帮助用户判断适合派什么任务。

## 4. 业务规则

- BR-1（2026-09-13 修订）：**不做全量共享**。私人（scope=user）记忆默认不外发；候选（status=candidate）与已拒绝记忆不参与召回；发给外部智能体的上下文按「当前任务 / 当前项目 / 用户授权范围」组装。
- BR-2：外部智能体不直接写入 Obsidian；统一经阿罗德斯审核后由阿罗德斯写入，保证格式一致。
- BR-3：同一工作区内智能体身份唯一；同一智能体可分别接入多个不同工作区。
- BR-4：同步到 Obsidian 是幂等的——重复同步不产生重复条目，已有条目按记忆标识更新。
- BR-5：派发会改动文件或执行命令的高风险任务前，必须经用户确认。
- BR-6：对话或任务执行期间，用户可随时中止。
- BR-7：外部智能体不可用时，界面明确提示，且不影响其他智能体的接入与对话。
- BR-8（2026-09-13 新增）：只有阿罗德斯拥有可写记忆服务；外部智能体的写入一律降级为候选，任何模块不得绕过统一入口直接修改长期记忆。
- BR-9（2026-09-13 新增）：**所有**长期记忆读写必须经统一入口 `memoryService` —— 主对话链路、显式「记住 / 忘了」指令、研讨会学习沉淀、外部智能体写入均不得例外。
- BR-10（2026-09-13 新增）：记忆的来源身份由服务端按通道确定（用户界面通道 = user；外部通道 = 调用方自报 id，但不得自称 user）；请求体不得覆盖来源。

## 5. 数据与边界

核心业务实体：

- 工作区：按项目隔离的容器，包含接入的智能体、候选与已确认记忆、对话记录。
- 智能体：可接入的 AI 服务（阿罗德斯自身、Codex、DeepSeek Harness 及未来其他），具有类型、可用性与能力。
- 记忆：统一格式的记忆条目（内容、类型、作用域、来源、证据、置信度、审核状态、时间、归属工作区）。
- 对话：用户与某智能体在某工作区内的多轮交流。
- 接入关系（连线）：工作区与智能体之间的成员关系。

关系：一个工作区可接入多个智能体；一个工作区包含多条记忆与多组对话；一个智能体可接入多个工作区。

## 6. 非功能需求

- 性能：智能体回复在可接受时间内返回；一次性委派场景允许分钟级等待，界面需有进行中状态。
- 可用性：外部智能体不可用时不影响其他功能；关键操作（接入、审核、同步、派任务）有明确反馈。
- 安全：高风险任务必须确认；外部智能体仅在用户授权范围内执行操作；私人记忆默认不外发。
- 可维护性：新增一种智能体接入的改动成本低（每种智能体一套独立接入适配，核心不变）。
- 一致性：同步完成后，已确认记忆与 Obsidian 中的内容一致；重复同步不产生脏数据。

## 7. 整体验收标准

- 场景一（接入与对话）：给定工作区存在且本机有 Codex 与 DeepSeek Harness；当用户把两者接入并发起对话；则两者均能回复，回复展示在各自对话区。
- 场景二（候选审核）：给定 Codex 在工作区提交一条候选记忆；当用户审核通过；则该记忆成为已确认长期记忆，其他智能体在上下文包中可见；未审核的候选对任何智能体都不可见。
- 场景三（Obsidian 同步）：给定工作区有若干条已确认记忆与若干条候选；当用户点击同步到 Obsidian；则仅已确认记忆以统一格式出现在 Obsidian 知识库并生成索引；再次同步不产生重复。
- 场景四（高风险确认）：给定用户向智能体派发修改代码的任务；当执行即将开始；则出现确认提示，用户确认后才执行。
- 场景五（私人记忆不外发）：给定存在 scope=user 的记忆；当向外部智能体发送上下文包且未显式授权；则该记忆不在上下文包内。
- 场景六（权威方向）：给定用户在 Obsidian 中修改了某条记忆并补写「我的补充」；当再次同步时；则自动生成区被更新，**用户手写内容不被覆盖**；当执行「从 Obsidian 重建」时；则 SQLite 索引以 Obsidian 内容为准被重建。
- 场景七（记忆一致性）：给定用户说出「忘了 X」；当指令处理完成后；则 X 不再出现在召回与用户画像中，且其 Obsidian 笔记移入归档区（可从归档恢复）。

## 8. 开放问题

- 长对话上下文的压缩策略（对话过长时如何处理）——实现期确定。
- 候选记忆的自动审核策略（是否允许高置信度的阿罗德斯自产记忆免审核）——实现期确定。
- 画布升级（FR-9）的具体交互（拖拽、缩放、连线样式）待卡片版验收后细化。
