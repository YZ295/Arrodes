# Arrodes 产品构想反证记录（2026-09-06）

## 核心任务

用户真正需要的不是“拥有视觉、语音、记忆和许多 Agent”，而是在陌生任务中不用不断停下来解释现状和寻找下一步。Arrodes 应观察当前状态、给一个动作、验证完成，再继续。

## 观点拆分

| 用户提出的方向 | 判断 | 原因 |
|---|---|---|
| 做私人 AI 管家 | 保留，但收窄定义 | “管家”无法直接验收，必须落到观察、单步指导、验证、授权和记忆闭环 |
| 看见并认识用户 | 修改 | 本机单用户身份已由账户和记忆提供；人脸识别增加隐私与误识别成本，却不能证明系统理解用户正在做什么 |
| 摄像头指导机器人和焊接 | 放在屏幕识别之后；先验证低风险装配，焊接推迟 | 小零件、手部遮挡、视角和安全风险使焊接不能作为首个可控实验 |
| 看屏幕教用户开发 | 确认为第一阶段 | 与现有基础最接近、反馈可观察；但必须输出结构化观察并跟踪变化，不能退化成“截图后聊天” |
| 外语视频转中文字幕 | 保留为独立模式 | 它依赖系统音频、流式 STT、翻译和字幕时序，不是步骤指导状态机；强行统一会产生错误抽象 |
| 处理和删除文件 | 保留，但重做安全语义 | 当前永久删除缺少回收站与撤销；私人管家首先要可信，而不是操作数量多 |
| 按规范写论文 | 委派给文档流水线 | 需要模板、引用、结构、渲染和视觉校验，不能由普通聊天加文件写入可靠完成 |
| 视觉和语音常驻 | 改为“始终可用、显式开启” | 全天采集会带来隐私、误触发、发热和资源竞争；大模型全 GPU 常驻也不符合 8 GB 显存约束 |
| 加强自身编码能力 | 删除主线投入 | 用户已有 Codex、WorkBuddy、Hermes、Crow5 和 DSH；重复建设不会增加核心价值 |

## 关键盲点

### 1. “能看见”不等于“能验证”

单张图片描述只能回答画面里大概有什么。指导需要知道任务目标、当前步骤、上次状态、期望证据和失败条件。缺少这些状态时，连续截图只会产生连续描述。

### 2. “认识我”不是第一阶段的必要条件

Arrodes 服务于本机单用户。系统可通过登录账户、显式档案和长期记忆知道用户是谁。第一阶段真正缺失的是识别手、工具、工件和任务进度；先做人脸识别会把资源投入到低价值问题。

### 3. 多个场景没有完全相同的机制

现实指导是观察—行动—验证；视频翻译是连续音频—转写—翻译—字幕同步；论文交付是约束—结构化生成—渲染—校验。它们可以共享权限、日志、感知事件和记忆，但不应共享一个万能业务流程。

### 4. “主动”可能损害信任

没有任务边界的主动观察容易误判、打断用户，并让用户不清楚摄像头和屏幕是否正在被记录。首版采用显式陪伴会话和明显状态指示，比全天自主监视更可执行。

### 5. 现有 Agent 能力可能绕过管家安全边界

外部 Agent 直派、桌面操作和永久文件删除如果没有统一预览、确认、执行日志和结果验证，会让“能够代办”变成最危险而不是最有价值的能力。

## 当前不可执行的承诺

| 承诺 | 缺失机制 | 为什么现在不可执行 |
|---|---|---|
| 自动认识用户并理解现场 | 身份登记、视觉特征、时序跟踪、隐私和误识别处理 | 当前人物识别主要来自文本，单图视觉无法稳定维持身份与动作状态 |
| 实时指导焊接 | 多视角/近距画面、步骤证据、安全知识、置信度门槛 | 遮挡和误判可能造成烫伤、短路或设备损坏 |
| 外语视频实时中文字幕 | 系统音频采集、流式 STT、翻译缓冲、字幕同步 | 当前屏幕采集关闭音频，现有字幕主要显示 AI 回复 |
| 可靠按格式交付论文 | 文档模板解析、引用模型、DOCX/PDF 渲染与视觉验收 | 文本文件写入不能证明页边距、题注、目录和引用格式正确 |
| 语音视觉大模型全部本地常驻 | 统一资源调度和足够显存 | 8 GB GPU 无法同时容纳当前重型视觉与高质量 TTS 模型 |

## 当前第一阶段假设

> 在用户显式共享屏幕并给出观察目标后，Arrodes 能否可靠识别当前应用、活动、关键文字和不确定点，并在画面未变化时避免重复分析？

用户明确要求先开发屏幕识别，再开发摄像头观察本人。开发顺序已据此调整；这不会改变实体任务状态识别仍是第二阶段最高风险假设。

## 第二阶段最高风险假设

> 给定普通摄像头画面，Arrodes 能否在用户不持续用文字解释的情况下，可靠区分一个实体任务的步骤是否完成？

这是最应先验证的假设。若它不成立，添加更多模型、语音、Agent 和页面都不能形成目标产品。

## 最小验证实验

第二阶段已确认任务：使用用户已有的 Arduino 套餐，指导用户搭建并运行一个低压、低风险的外接 LED 闪烁电路。

实验范围：

- 固定一个摄像头和固定光照；
- 使用预先定义的 5–8 个步骤；
- 每一步都有机器可观察的完成证据；
- 只给一个下一步；
- 看不清时请求调整画面；
- 允许中途关闭并恢复任务；
- 不进行任何自动硬件控制。
- 不把仅凭色环识别电阻阻值作为首轮必要条件；优先使用套件标签或用户确认，避免同时验证两个高不确定问题。

通过信号：大多数步骤无需用户文字解释即可正确推进，系统不跳步，并能在遮挡或证据不足时停止猜测。

失败信号：用户仍需不断描述当前状态、系统经常重复或跳步、无法从中断恢复，或者低置信度时继续给出确定指令。

停止条件：若限定场景、固定视角下仍无法可靠验证步骤，暂停现实指导主线；保留屏幕陪练，重新评估传感器、模型和交互方式。

## 用户裁决

用户进一步明确开发顺序：先完成电脑屏幕识别，再开发摄像头看见用户。Arduino 套餐保留为第二阶段真实验收；届时先识别具体开发板、摄像头条件和套件组件，再冻结接线图。
